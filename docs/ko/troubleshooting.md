# 문제 해결

## 프로세스가 시작되지 않을 때

- `data_dir`가 실제로 존재하는지 확인합니다.
- 인증서, 개인 키, CA 인증서 경로가 올바른지 확인합니다.
- 로그 경로가 지정되었다면 해당 파일에 쓰기 권한이 있는지 확인합니다.

## GraphQL 접속이 되지 않을 때

- 클라이언트 인증서를 함께 제시하고 있는지 확인합니다.
- 서버 실행 시 전달한 `--ca-certs`가 클라이언트 인증서 검증에 사용되므로, 인증서 체인이 일치하는지 확인합니다.

## 클러스터가 정상 연결되지 않을 때

- `peer_srv_addr`와 `peers` 값이 실제 네트워크와 일치하는지 확인합니다.
- peers 간 방화벽 정책과 라우팅을 점검합니다.
- 노드별 인증서 및 이름 정책이 상호 검증 요구 사항과 맞는지 확인합니다.

## 동작 중이던 프로세스가 종료될 때

Giganto는 ingest, publish, peer, retention 서브시스템을 관찰합니다.
이들의 진입 작업 중 하나가 스스로 종료되면 노드는 해당 서브시스템 없이
계속 동작하지 않고, 평소와 같은 종료 절차를 수행한 뒤 실패 상태로
종료합니다. 따라서 실패 시 재시작하도록 설정된 서비스 관리자가 노드를
다시 띄웁니다.

- 로그에서 `entry task ended abnormally`를 확인합니다. 이 기록은 작업
  이름(`name`), 노드가 동작 중에 관찰된 것인지 종료 절차에서 회수된
  것인지(`phase`), 무슨 일이 있었는지의 분류(`outcome`은 `early_exit`,
  `error`, `panic`, `cancelled` 중 하나), 그리고 작업이 얼마나 오래
  실행되었는지(`age`)를 담고 있습니다.
- 서브시스템은 실패가 발생한 지점에서 자신의 원인도 함께 남깁니다(예:
  `Ingest subsystem terminated unexpectedly`). 그 줄이 이유를 말해 주고,
  위의 기록이 무엇이 끝났는지를 말해 줍니다.
- `generation ended degraded`는 노드가 이미 종료 절차에 들어간 뒤에
  무언가가 비정상적으로 끝났다는 뜻입니다. 종료 절차는 끝까지 진행되고
  요청된 재부팅이나 전원 차단도 그대로 수행되지만, 종료 상태는 실패를
  보고합니다. 설정 재적재만은 예외로, 노드는 다음 세대를 시작하고 실패
  사실은 로그로만 남깁니다.
- `shutdown drain could not read the top-level tracker` 또는 `the web
  PCAP reaper tracker`에 대한 같은 줄은 세대가 degraded로 끝나는 또
  하나의 원인입니다. 앞선 패닉으로 종료 절차의 작업 관리용 잠금 하나가
  못 쓰게 되었다는 뜻입니다. 그래도 종료 절차는 새 작업 수용을 멈추고,
  실행 중이던 작업을 취소했으며, 추적 중인 작업이 모두 반환된 뒤에야
  데이터베이스를 닫았습니다. 이 메시지는 무언가가 중간에 끊겼다는 것이
  아니라 그 지점에 어렵게 도달했다는 기록입니다. 남은 작업 목록 없이
  개수만 보고하며 작업 레지스트리를 읽을 수 없었다고 말하는 드레인
  라운드도 원인이 같습니다.
